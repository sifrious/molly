Molly is a local-first Laravel coding agent. The model can propose the work. Evidence decides whether the work is done.

Get started Read the docs View on GitHub

Named for Molly Bloom, whose chapter of Ulysses begins and ends with yes. Why the name

The agent does not grade its own homework.

A model saying its own work is correct can never turn failed test evidence into a pass.

Task boundary
One small, named piece of work. Not a backlog.
Allowed files
The agent may change only the files the task names.
Required Pest test
Real Pest runs. The JUnit evidence has to name that test file.
Protected tests
The acceptance test is locked by default. The agent cannot rewrite the exam.
Tarpit gate
Unresolved accidental complexity keeps the task incomplete.
Persisted evidence
Every attempt, output and receipt is saved for review.

Bound → Execute → Verify → Inspect → Accept

  1. Bound

    Name the task, the files it may touch, and the Pest test that must pass.

  2. Execute

    The agent proposes a change. Molly applies only allowed-file edits.

  3. Verify

    Pest runs the required test. Tarpit reviews complexity. Clever records measurements on the side.

  4. Inspect

    Attempts and receipts stay on disk. Bounded retries keep the earlier evidence.

  5. Accept

    A person reads the diff, runs the wider suite, and decides whether to integrate.

A passing test supports a claim. It does not prove the entire application is correct. Molly never commits for you.

Why Molly

Molly is named for Molly Bloom, from James Joyce’s Ulysses. Her chapter, “Penelope”, opens with yes and closes with one of the most famous yeses in literature.

yes I said yes I will Yes.

James Joyce, Ulysses (1922)

For the chapter and its adaptations, see Nick Bentley and James Peacock, “Stories into song: theory and co-creative practice of adapting literary fiction into pop and rock songs”, Adaptation, Oxford Academic, 2024.

Software is full of yes. Yes, we can build it. Yes, the model can change the file. Yes, the abstraction can be added. Molly’s yes has to be earned.

There is a plainer reason too. My family has always called me Molly.Mary Perry

Molly standalone

Terminal-first. No Bloom required.

Install into a Laravel app, choose Ollama or Amp, and run tasks from Artisan. File scope, protected tests, Pest, Tarpit, Clever, retries, history, the local web UI and local MCP tools all work on their own.

Standalone QuickStart

Molly with Bloom

Optional. Bloom owns the workspace, Molly owns the evidence.

Bloom keeps the worktree, branch, diff, agent session and pull request flow. Molly exports a task contract for that workspace and keeps the tests, attempts, receipts and approval state. Molly never creates a second Bloom worktree.

Bloom QuickStart

Generation is cheap. Judgment isn’t.

Prioritize

A planning principle

Doing the wrong thing efficiently is still doing the wrong thing. Before a task runs, ask what should happen next, what is actually blocking progress, what the smallest independently verifiable slice is, and what can be left out.

Seams

An architecture principle

Use the seam the framework already gives you. Events, contracts, middleware, bindings, drivers, commands, policies, jobs and configuration are where Laravel was designed to change. Prefer them before inventing new architecture.

Tarpit

A blocking gate

A complexity review that runs separately from Pest and can keep a task incomplete. It is not a quality score, and a model cannot override it. Complexity is adjacent to correctness.

Clever

Advisory measurement

Before and after measurements recorded next to the run. They describe the change. They are never combined into one score and never decide a verdict. Read more at clever.mary.win.

Cleverness Is A Loan

At Laracon US 2026, Mary Perry argued that cleverness carries a cost. Every abstraction, novel mechanism or architectural trick is a loan someone has to service later.

Molly applies that talk. AI makes generation cheaper, so restraint, prioritization, seams and verification matter more. Tarpit and Clever continue the same line of thinking.

Local first, on purpose

Ollama is a first-class agent. The QuickStart talks to Ollama on loopback with no paid account.

If local Ollama fails, Molly stops and says why. It does not quietly fall back to a hosted provider. Amp and any hosted choice are explicit settings.

Molly uses stronger process isolation when the host supports the required Linux sandbox features. molly:doctor reports whether that safe workflow is available on your machine.

Laravel knowledge, advisory only

A local, version-aware graph covers queues, routing, testing, validation, the service container, Eloquent and events. NativePHP Desktop and Mobile live in their own namespaces, and so do Tarpit notes.

Knowledge can inform a proposal. It cannot widen the allowed files, touch a protected test, or declare a task complete.

What ships today, and what does not

Ships today

  • Bounded Laravel coding tasks
  • Protected acceptance tests
  • Pest verification with false-green protection
  • Required Tarpit review
  • Separate Clever measurements
  • Bounded retries and persisted attempt history
  • Local Ollama and explicit Amp integration
  • Local MCP tools and a local web UI
  • Project graph and Laravel knowledge graph
  • NativePHP knowledge namespaces
  • Git-tracked decisions, journals and source snapshots
  • Optional local component previews

Not yet

  • Verified Orb identity
  • Remote execution selection
  • Molly opening pull requests itself
  • Molly merging pull requests itself
  • A compiled Bloom macOS integration
  • Visual previews inside Bloom
  • Laravel knowledge beyond the areas listed above

Molly records approvals, pull requests and merges that people make. Humans still make the final integration decision.

Install the current release

Molly needs PHP 8.3 or later, Laravel 12 or 13, Pest, and a working database. It installs from the public GitHub repository until it is listed on Packagist.

composer config repositories.molly vcs https://github.com/sifrious/molly
composer require --dev sifrious/molly:^0.1.1
php artisan vendor:publish --tag=molly-config
php artisan migrate

Then follow the standalone QuickStart. The v1 install line appears here once v1 is tagged and a fresh install is proven.
