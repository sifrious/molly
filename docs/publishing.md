# Publish the documentation

This is the publishing plan for `molly.mary.win`. The documentation source is ready for review in `docs/`. Enabling GitHub Pages and changing DNS are separate release steps.

## Destination and source

| Setting | Planned value |
| --- | --- |
| Repository | `sifrious/molly` |
| Public hostname | `molly.mary.win` |
| Publishing source | `main`, `/docs` |
| Builder | GitHub Pages' built-in Jekyll build |
| Default address before the custom domain | `https://sifrious.github.io/molly/` |
| Published content | Documentation HTML and CSS |

Keep the Markdown beside the package so code changes and documentation changes can share a commit. The site uses a small HTML layout, CSS, and relative Markdown links. Core reading and navigation need no JavaScript.

GitHub supports publishing directly from a branch's `/docs` directory. The documentation check workflow builds the site without deploying it. No separate docs repository or generated-content branch is needed. [GitHub publishing sources](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Read-only checks on September 17, 2026 found no Pages site through the repository API and no public A or CNAME answer for `molly.mary.win`. The `mary.win` nameservers were `dns1.registrar-servers.com` and `dns2.registrar-servers.com`. Recheck these facts immediately before activation. An empty DNS answer does not establish domain ownership or editing access.

## 1. Finish the documentation checks

Merge the reviewed documentation into `main`. Confirm the documentation build passes, internal links resolve, and a phone-width page has usable navigation and readable code examples. Check the getting-started commands against a clean Laravel application before calling the first-run guide release verified.

The current guide identifies model setup examples separately from Molly's recorded live-model evidence. Publishing the docs does not change that distinction or create an alpha release tag.

## 2. Enable the default Pages address

In the repository's **Settings → Pages**, choose **Deploy from a branch**, select `main` and `/docs`, then save. Keep `docs/_config.yml` at these initial values:

```yaml
url: https://sifrious.github.io
baseurl: /molly
```

Wait for the Pages build to succeed. Open the default address, follow the first-run and reference links, and check that CSS loads. GitHub Pages runs the Jekyll build; the Molly application and Ollama remain local. [GitHub Pages and Jekyll](https://docs.github.com/en/pages/setting-up-a-github-pages-site-with-jekyll/about-github-pages-and-jekyll).

## 3. Verify the proposed hostname

Check the Pages settings for the `sifrious` account. If that account already verifies `mary.win`, the verification covers the immediate `molly.mary.win` subdomain. Otherwise, verify `molly.mary.win` using the TXT name and value generated by GitHub. Keep the TXT record after verification. Do not move an existing verification from another account as part of this setup. [GitHub domain verification](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages).

This step requires access to the account's Pages settings and the domain's DNS records. Use the generated TXT value exactly; the value cannot be filled in ahead of time.

## 4. Connect the subdomain

Save `molly.mary.win` as the repository's custom domain before adding the routing record. Confirm that the publishing source contains `docs/CNAME` with one line:

```text
molly.mary.win
```

Then add this DNS record:

| Type | Host | Target | TTL |
| --- | --- | --- | --- |
| CNAME | `molly` | `sifrious.github.io` | Provider default |

The target has no `https://` prefix and no `/molly` path. Inspect any existing record for the exact hostname before replacing it. Keep unrelated `mary.win` records unchanged. [GitHub custom subdomain setup](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site#configuring-a-subdomain).

In the same cutover, change the site configuration and let Pages rebuild:

```yaml
url: https://molly.mary.win
baseurl: ""
```

The empty `baseurl` matters. Documentation lives at the custom domain's root, so retaining `/molly` would break asset and navigation URLs.

## 5. Confirm DNS, HTTPS, and navigation

Check the CNAME:

```bash
dig +short molly.mary.win CNAME
```

The answer should be `sifrious.github.io.`. Wait for GitHub's domain check and TLS certificate, then enable **Enforce HTTPS** in Pages settings. [GitHub HTTPS setup](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https).

Check the published responses:

```bash
curl -I https://molly.mary.win/
curl -I https://molly.mary.win/getting-started.html
curl -I https://molly.mary.win/assets/docs.css
curl -I http://molly.mary.win/
```

Expect successful HTTPS responses and an HTTP redirect to HTTPS. Follow links into `reference/`, test keyboard navigation, and open an unknown path to check the 404 page. Allow time for DNS and certificate issuance before treating a pending check as a failed deployment.

The public URL can replace the README's publishing-plan link only after these checks pass.

## Updating and rolling back

After activation, changes to `docs/` on `main` publish through Pages. Review the documentation build before merging. A content rollback is a revert of the documentation commit followed by a successful Pages build.

To retire the hostname, remove its routing CNAME before disabling the Pages site or removing the custom domain. Keep the verification TXT record. To return to the default Pages address, restore the original `url` and `baseurl` values and remove `docs/CNAME` as part of that coordinated change. Confirm the default address after rebuilding.
